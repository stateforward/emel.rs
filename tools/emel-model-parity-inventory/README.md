# emel-model parity inventory

This maintained tool generates the primary source and Rust inventories that drive the full
`emel-model` parity program. It does not claim runtime parity. All input is read from exact Git
objects. C++ declarations are accepted only from real JSON AST nodes emitted by the pinned Clang;
Rust declarations are accepted only after `syn` parses every committed Rust source file.

Every compile-database include root under a mutable build dependency directory is recursively hashed
with normalized relative paths and file bytes, checked against a pinned digest, copied into the isolated
extraction directory, and recorded in `snapshots/pinned-external-includes.tsv`. Clang reads the checked
copy rather than the mutable build directory.

The canonicalization contract is `emel-model-parity-inventory/v1`:

- paths are case-preserved, forward-slash Git paths with no empty or dot segments;
- named compiler identities include side, owner path, closed item kind, qualified name, and canonical
  compiler signature;
- anonymous C++ declarations include their qualified parent and exact spelling line and column;
- macro declarations use spelling locations, never mutable expansion or temporary paths;
- scanner identities include owner path, scanner kind, exact line and column, and a token stream with
  whitespace and comments removed;
- each semantic hash is SHA-256 over length-delimited schema version, side, path, kind, identity, and
  canonical payload fields.

Extraction fails closed for source, compiler, compile-database, schema, parser, manifest, duplicate-ID,
or deterministic-output drift. The seven TSVs and both pinned snapshots are one exact recoverable
nine-target generation. Each canonical target-owner directory has a stable
`.emel-model-inventory.lock` file outside the generation: one for the seven-TSV artifact directory and
one for the Rust repository's snapshot directory. Lock-file paths are canonicalized, globally sorted,
deduplicated, identity-checked, and acquired as one set with a bounded deadline. Symlinked or multiply
linked lock files are rejected, and replacing a bound owner or lock identity fails closed. On Unix, the
tool retains directory capabilities and performs transaction reads and mutations relative to those
capabilities. It also locks every canonical owner ancestor through `/` before the owner lock files. The
root lock deliberately serializes all cooperative writers on the host; that throughput cost keeps one
cooperative lock domain even if a non-cooperative process renames and recreates every owner. On Windows,
the retained owner-directory identity handles and original lock-file handles explicitly share reads and
writes but not deletion, so another process cannot rename, delete, or recreate either pathname while a
generation lock is live. Extraction holds every exclusive OS-backed lock from entry through
recovery, staging, publication, the terminal manifest, and cleanup. Standalone validation and deterministic
checking hold every shared lock for their complete identity, build, read, and comparison intervals. Sharing
any Unix ancestor, including `/`, therefore excludes a writer; this tool favors rename-stable publication
over concurrent disjoint Unix generations. Lock files are never renamed or deleted by the tool, and process
exit closes every retained handle automatically before the next recovery. A persistent identity token in
every owner is `in-progress` before target mutation
and becomes one equal `complete` identity only after transaction cleanup; readers require the same complete
identity before and after their full interval. Recovery reconciles an interrupted or mismatched token set
before acceptance. Validation also refuses either transaction journal and digest-binds both snapshots.
Artifacts are staged and validated before publication. Reconciliation never treats a name match as parity proof:
unique counterpart candidates remain `partial` and every row remains an explicit open gap until later
implementation lanes bind real proof.

The compile database must contain exactly one canonical row for every `.cpp` translation unit under
the pinned Git object's `src/emel/model/` and `tests/model/` trees. The expected path set is derived
from that immutable object manifest rather than a file count or the source worktree. Missing,
duplicate, and unexpected model rows fail before Clang starts. The pinned database is regenerated by
configuring the exact source commit with the audit-native compiler, architecture, host-feature, test,
and dependency-source settings; it is never repaired by inserting a tool-only compile row.

## Bounded Rust preflight

Build the tool first, then run the committed Rust-only preflight through the external watchdog. Bash
is a required portable Unix prerequisite; invoking the script through another shell hard-fails before
the target starts. The
outer deadline includes target launch time; the shorter internal monotonic deadline bounds every Git
child after the Rust process starts. The wrapper captures and forwards child stdout and stderr, sends
SIGTERM to the target process group at the deadline, sends SIGKILL after the grace period, reaps the
target, and reports timeout with exit code 124. It retains process-group ownership after the leader exits;
if a successful or crashed leader leaves descendants behind, the wrapper terminates the group, verifies it
is gone, forwards the captured streams, and returns exit code 125 instead of reporting false completion.

```sh
cargo build --locked -p emel-model-parity-inventory
tools/emel-model-parity-inventory/scripts/run-with-deadline.sh \
  --seconds 30 --grace-seconds 2 -- \
  target/debug/emel-model-parity-inventory preflight-rust \
  --rust-repo . --rust-commit HEAD --deadline-seconds 20
```

The preflight resolves the requested revision once, then reads the tree, path/OID manifest, and blobs only
through that immutable commit and tree identity. It re-resolves the requested revision before acceptance and
rejects movement. Dirty and untracked worktree files do not affect its counts or identities.

Before a full Clang campaign, the bounded Rust-only preflight can prove that the exact committed model
crate parses and can report its deterministic inventory counts without reading dirty worktree content or
publishing artifacts:

```sh
cargo run --locked -p emel-model-parity-inventory -- preflight-rust \
  --rust-repo . \
  --rust-commit HEAD \
  --deadline-seconds 20
```

The output binds the canonical repository path, requested and resolved commit, model-crate Git tree,
ordered blob-manifest digest, and disjoint non-test declaration, test, assertion, and SML transition
counts. The command invokes neither Clang nor artifact publication.

## Parser fuzzing

The pinned fuzz workspace carries curated valid and malformed corpora for all parser families. Copy
the committed seeds into a private temporary directory before each run: libFuzzer may add minimized
inputs to its corpus, and those generated inputs must never change the reviewed source candidate.
Run each target from `fuzz/` so cargo-fuzz loads the copied curated seeds instead of starting empty:

```sh
work=$(mktemp -d)
for target in inventory_tsv clang_ast_stream schema_tsv; do
  mkdir -p "$work/corpus/$target" "$work/artifacts/$target"
  cp -a "corpus/$target/." "$work/corpus/$target/"
  CARGO_TARGET_DIR="$work/target" cargo fuzz run "$target" "$work/corpus/$target" -- \
    -max_total_time=10 -seed=424242 -artifact_prefix="$work/artifacts/$target/"
done
```

`schema_tsv` uses a typed leading-byte selector (`I`, `C`, or `G`) and reaches the inventory,
coverage, and gap parsers through production validation APIs.
